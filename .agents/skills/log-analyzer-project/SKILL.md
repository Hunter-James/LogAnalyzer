# Log Analyzer Project

## Начало работы

1. Прочитать корневые AGENTS.md и CLAUDE.md.
2. Проверить git status; не трогать несвязанные изменения и untracked-файлы.
3. Найти существующий путь реализации через rg, затем менять минимальное число модулей.
4. После изменения проверить реальный сценарий, собрать exe и сделать подробный коммит на русском.

## Карта проекта

- src/main.py: запуск Qt, crash-log, обработка файлов из sys.argv.
- src/config.py: дефолты и нормализация settings.json.
- src/gui/window.py: главное окно, восстановление сессии, открытие файлов, применение настроек.
- src/gui/settings.py: диалог настроек; поведенческие параметры возвращаются в MainWindow.
- src/gui/tab_manager.py: группы, панели, вкладки файлов, drag-and-drop и прокрутка.
- src/core/workers.py: чтение .log, .txt, .gz, .zip, .7z, .rar; FilterWorker выполняет поиск, группировку соседних дублей и подготовку меток ERROR/WARN в фоне.
- src/core/models.py: очередь поиска (один активный и последний отложенный запрос), защита от устаревших результатов.
- src/gui/log_viewer.py: debounce поиска 300 мс, применение фильтров и отображение готовых меток.
- tests/test_search.py: регрессии поиска, отмены, очереди запросов, группировки и меток.
- src/core/single_instance.py: локальный Qt-канал между повторными запусками приложения.
- src/core/models.py и src/core/group_stats_worker.py: единая логика партий и сводки группы.
- src/core/file_associations.py: регистрация Log Analyzer как обработчика файлов текущего пользователя Windows.
- LogAnalyzer.spec: однофайловая PyInstaller-сборка с log_perfect.ico.

## Подтвержденные правила поведения

- .log регистрируется как поддерживаемый тип по умолчанию; .zip включается отдельно в настройках.
- Windows 11 не разрешает приложению без участия пользователя назначить default app. Регистрировать ProgID и Capabilities в HKCU, а выбор по умолчанию открывать через ms-settings:defaultapps?registeredAppUser=Log%20Analyzer.
- Путь от Проводника приходит через sys.argv; уже открытый файл нужно активировать, не дублировать.
- Работает один экземпляр приложения: на Windows первый процесс удерживает именованный mutex и слушает QLocalServer, повторный запуск передает ему пути через QLocalSocket и завершается. Запуск без пути активирует существующее окно.
- Лента групп должна оставлять доступными стрелки прокрутки и кнопку добавления. Колесо над лентой прокручивает группы горизонтально; drag групп сохраняет перестановку.
- Изменения интерфейса групп не должны затрагивать DraggableTabBar файлов.
- Изменения партий должны одинаково применяться в LogModel и GroupStatsWorker.

## Производительность поиска

- Не включать tracemalloc по умолчанию: на проверенном логе ~448 МБ / 2,96 млн записей старый поиск ERROR занимал ~10 с с трассировкой и ~2,35 с без неё. Диагностика включается переменной окружения `LOG_ANALYZER_TRACE_MEMORY=1`; RSS-индикатор работает независимо.
- Не вызывать wait() из обработки нового поискового запроса. Отменять активный проход внутри цикла, хранить только последний запрос и запускать его по системному QThread.finished. Сигнал FilterWorker.finished передаёт результат как object, без конвертации миллионов индексов в QVariantList.
- QListView результатов использует Batched layout по 2000 строк: не возвращать синхронную раскладку миллионов совпадений.
- Группировка и метки выполняются до публикации результата. UI применяет готовые индексы и максимум 200 меток; смена темы только перекрашивает их.
- При выгрузке/закрытии останавливать search_timer и вызывать model.stop_filtering(), отменяющий также отложенный запрос. Результаты отменённых и заменённых воркеров игнорировать.
- Literal-поиск сохраняет lower()-семантику Unicode; regex использует re.IGNORECASE, невалидный regex трактуется буквально. Поиск с переводом строки сохраняет завершающий newline full_line.

## Проверка

- Сначала проверить доступность Python и импорт PyQt6: системный python/py может попадать в Windows Store shim. Старый .venv с Python 3.14 может не запускаться после переноса проекта. Проверенное окружение этой машины: .venv-search\Scripts\python.exe (Python 3.12, PyQt6/Qt6 6.10.2), локально исключено через .git/info/exclude.
- Тесты: `.venv-search\Scripts\python.exe -X utf8 -m unittest discover -s tests -v`. Для autopep8 также нужен `-X utf8` из-за русского setup.cfg; в тестах с настройкой sys.path использовать `--ignore E402`.
- Проверять синтаксис измененных Python-файлов через ast.parse.
- Для Qt-компонентов использовать QT_QPA_PLATFORM=offscreen и проверять свойства виджетов и PNG-рендер.
- Изменения запуска проверять двумя процессами EXE: второй должен завершиться, а переданный ему файл появиться в первом.
- Выполнять git diff --check.
- Проверять обработку реальных пользовательских файлов, когда они доступны и относятся к задаче.

## Выпуск

1. Закрыть только процессы, запущенные из dist\LogAnalyzer.exe, если они блокируют файл.
2. Собрать dist\LogAnalyzer.exe через LogAnalyzer.spec. В окружении Codex перед сборкой ограничить PATH до `%SystemRoot%\System32;%SystemRoot%` и вызывать Python полным путём. Иначе PyInstaller подхватывает ucrtbase.dll и api-ms-win-crt-*.dll из bundled libheif, и EXE падает при импорте QtWidgets. После изменения PATH использовать `--clean`. Можно собирать в build/search-release, проверить запуск, затем копировать EXE в dist.
3. Проверить размер, дату и сигнатуру MZ.
4. Выполнить smoke-запуск нового exe и закрыть только созданные тестом процессы.
5. Ставить в индекс только файлы текущей задачи и создавать подробный русский коммит.
6. Стабильные релизы оформлять тегом vX.Y.Z, именем LogAnalyzer-X.Y и прикладывать dist\LogAnalyzer.exe под именем LogAnalyzer.exe. Описание составлять на русском по всем изменениям от предыдущего релизного тега.
