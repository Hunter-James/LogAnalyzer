# Краткое заключение

## Область и интерфейс

- Кнопка «Краткое заключение» в нижней полосе журнала анализирует весь текущий загруженный файл независимо от фильтров. Вычисление идёт в `ConclusionWorker`, закрытие диалога отменяет обход через общий реестр потоков.
- В контекстном меню партии «Анализ партии…» заключение строится при существующем обходе `LogModel.analyze_batch`, до подробных метрик.
- Ссылки открывают исходную логическую запись в нижней панели диалога. Номер записи не равен номеру физической строки многострочного файла.
- Другие вкладки и файлы группы не объединяются. Это явно указано в интерфейсе. Существующая разметка партий ориентирована на L2; для параллельных отчётов L3 использовать итог всего файла.
- Порядок событий — порядок файла; timestamp без даты не сортируется, чтобы не переставлять события через полночь. Последняя ошибка означает последнюю записанную, а не обязательно действующую сейчас.

## Безопасность выводов

- Отсутствующее подтверждение формулировать: «не найдено в загруженных журналах».
- Соседство ERROR и остановки не доказывает причинность. Ближайшая предшествующая ошибка в пределах 20 записей показывается только как возможная связь.
- Последний `Caused by` берётся из той же многострочной записи; соседние независимые исключения не склеиваются в цепочку причин.
- Ошибки соединения считаются по записям ERROR/FATAL с явными сетевыми признаками. Интервал первой/последней записи не доказывает непрерывный простой и не определяет автоматически адресата (L3, БД или устройство).
- HTTP 200, отправка данных в принтер и наличие скана не доказывают сквозное завершение процесса.
- Смешанный/неизвестный профиль отключает специфические выводы о состоянии L2. Статусы L3 распознаются только по конкретным логгерам и форматам сообщений.
- В итог выводятся до трёх последних отчётов, счётчики учитывают все обнаруженные UUID.
- Новые сообщения/версии L2/L3 расширять только после проверки источника и добавления регрессии.
